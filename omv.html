OpenMediaVault: Manual de Ingeniería NAS

Guía integral que fusiona la lógica de comandos Linux con la gestión de servicios en red y almacenamiento persistente.

Caso Práctico: "Estudio de Edición 'Pixel Flow'"

Un estudio de video necesita centralizar 2TB de material bruto. Requisitos: 1. Una carpeta "BRUTO" donde todos leen pero solo el jefe de edición escribe. 2. Una carpeta "ENTREGAS" pública para que los clientes descarguen sin contraseña.

Desafío Técnico

Configurar jerarquía de permisos ACL y exposición de protocolo SMB para entornos Windows/Mac.

Meta de la Práctica

Lograr latencia mínima y asegurar que el montaje sea persistente tras reinicios.

1. Diccionario de Conceptos

El Montaje (Mountpoint)

En Linux, un disco no es una "letra D:". Es un dispositivo físico que debe "colgarse" de una carpeta. Si no hay montaje, el sistema ve el hardware pero no puede leer los datos.

/dev/sdb1 -> /srv/dev-disk-by-label-DATOS

SMB / CIFS

Protocolo de red que permite compartir archivos. Es el "traductor" que hace que una carpeta de Linux aparezca en el explorador de archivos de Windows.

Puerto estándar: 445 TCP

Tabla de Particiones (GPT)

Es el mapa del disco. Al hacer un "Wipe" en OMV, borramos este mapa para que OMV pueda dibujar uno nuevo optimizado para almacenamiento NAS.

Permisos ACL

Listas de Control de Acceso. Van más allá del simple (Lectura/Escritura), permitiendo definir qué usuarios específicos pueden entrar a qué subcarpetas.

2. Ejecución Técnica

01

Identificación del "Sujeto"

Antes de tocar la web, debemos saber quién es nuestro servidor en la red y qué discos tiene físicamente conectados.

root@omv-server:~
// Averiguar la dirección IP para la interfaz web 
hostname -I
// Listar discos físicos detectados por el kernel 
lsblk

Explicación: lsblk (List Block Devices) te mostrará 'sda' (sistema) y 'sdb' (tu disco de datos). Es vital no confundirlos.

02

Preparación de la "Finca" (Almacenamiento)

1. Storage > Disks > Wipe

Elimina metadatos previos. Es como "aplanar el terreno" antes de construir.

2. Storage > File Systems > Create

Creamos EXT4. Aquí el disco recibe un UUID (Identificador Único Universal).

3. Mount

Activamos el punto de montaje. Sin esto, el comando df -h no mostrará el disco.

// Comprobar espacio real y montaje 
df -h

Este comando es vital: te dirá el % de uso y en qué carpeta exacta de Linux se ha montado el disco (ej: /srv/dev-disk-...).

03

Gestión de Accesos (Usuarios y Grupos)

Para el caso "Pixel Flow", necesitamos dos perfiles:

Usuario: 'jefe_editor'

Grupo: users, ssh, sudo.
Acceso total.

Usuario: 'cliente'

Grupo: users.
Acceso restringido.

¿Cómo se hace?

Ve a Users > Users. Crea los perfiles. OMV automáticamente sincroniza estos usuarios con el archivo /etc/passwd de Linux.

04

Exposición de Servicios (SMB)

Paso Crítico: Para que Windows vea las carpetas, SMB debe estar activo.

  • Services > SMB/CIFS > Settings: Enabled (Guardar).

  • Shares: Añadir la carpeta BRUTO. Desactivar "Public" (pide contraseña).

  • Shares: Añadir ENTREGAS. Activar "Public: Guest allowed" (No pide contraseña).

Mantenimiento de Emergencia (CLI)

Si la web se queda "congelada" o no aplica los cambios, estos comandos fuerzan al NAS a obedecer:

Reiniciar motor de configuración 
omv-salt deploy run nginx
omv-salt deploy run samba
Forzar reinicio de interfaces 
systemctl restart networking

Resumen del Flujo de Trabajo

Hardware (Disco) → Kernel (Reconocimiento) → OMV (Formateo/Montaje) → Linux (ACL/Permisos) → Protocolo (SMB) → Usuario Final.
